# Local live preview

D84 / v4.20. After a checked build or later save, prefer a reusable local live preview when the host permits a bounded foreground Node process and loopback browser access. It serves the project's **last checked standalone HTML/PDF pair**, rather than exposing the project directory. No dependency, remote hosting, daemon, global configuration or installation is introduced. An authorized local preview can stay open across normal edits; do not start a second server after each edit.

## Start or reuse

```sh
node /absolute/current-skill/assets/templates/brite/studio/scripts/live-preview.mjs \
  --project /absolute/saved-presentation
```

The command prints JSON with `running`, `reused`, `url`, `project`, `pid` and `idleMinutes`. Keep a newly started command in the host's bounded foreground task/session; retain its handle. Repeating the command for the same project reuses a responsive session and exits. Use the returned **actual url**, optionally adding `?lang=pl#presentation` or `?lang=en#presentation`, as Open presentation. Do not fabricate localhost addresses or open an older file tab and call it live. First migration still requires a checked stable export from this skill's edit/build helper; live preview does not rewrite or migrate a deck by itself.

Default port is dynamically allocated on 127.0.0.1; an explicit `--port` is optional. The random session URL is local to this computer and temporary. A different computer needs its own preview process. Respect host/browser/sandbox access restrictions. If starting or opening fails, keep the completed HTML/PDF and provide their direct links with a short explanation; do not install tools, escalate into a daemon, publish or bypass a rejected host route. Attachment-only hosts keep the offline delivery workflow.

## After later edits

Use the guarded same-project edit/build helpers normally. The preview checks the stable viewer, embedded PDF, export manifest/source hashes and settled save state. It sends a change event only after a coherent save is complete. During staging, locks, failed exports, interrupted/conflicting saves or unexported manual edits it retains its last checked pair. No new HTML is generated by the server. The page open in the external system browser (or an explicitly chosen host preview) then reloads automatically, preserving UI language, presentation/Templates view, active slide by stable ID, normal scroll anchor and template carousel positions. Reordering keeps the selected slide; deletion falls back to its nearest remaining index. A prompt/preview dialog defers reload until closed so reading/copying is not interrupted.

Windowed presentation mode is restored. Browser-native fullscreen may exit on navigation and cannot be silently re-entered without a browser-authorized user gesture. The agent should not promise native fullscreen persistence. Browser storage restrictions can limit position restoration. Verify actual automatic update plus matching PDF download when changing this helper; geometry/source checks alone do not prove live behavior.

## Stop and expiry

The EN/PL Live preview badge offers **Stop / Zatrzymaj**. It is hidden on presentation slides and print. Exit presentation mode to use it, ask the agent to stop, or press Ctrl+C in the foreground preview task. Agent commands:

```sh
node scripts/live-preview.mjs --project /absolute/saved-presentation --action status
node scripts/live-preview.mjs --project /absolute/saved-presentation --action stop
```

The server exits after 60 minutes without opening/refreshing the page, status checks or observed browser interaction; SSE heartbeats do not keep it alive. `--idle-minutes 1..240` changes this bounded period. After an explicit Stop or idle expiry the page says Stopped and keeps its already loaded deck/download. Restarting produces a new session URL; open the newly returned link. Status/stop uses only the project's validated session record. Never kill unrelated processes or assume a reused PID is safe to terminate.

State lives under `.brite/live-preview.json`, alongside existing internal recovery state. Stale known session metadata is archived only after its recorded process is no longer alive; unknown files/symlinks are refused. Stop removes only this session's own record. The server accepts loopback Host/same-origin requests, uses an unguessable per-session route, requires a session header for stop/activity and serves no arbitrary file paths or history/source directories. Exported HTML remains unchanged and carries no server/client injection, so downloaded/offline copies still work independently and require manual refresh or a new download.

## User wording

EN: “Your preview updates automatically after each checked save. Keep this tab open. Download PDF always uses the version shown here. Use Stop to end live preview; your saved HTML and PDF remain available.”

PL: „Podgląd aktualizuje się automatycznie po każdym sprawdzonym zapisie. Zostaw tę kartę otwartą. Pobierz PDF pobiera wersję widoczną w tym podglądzie. Zatrzymaj kończy podgląd na żywo; zapisany HTML i PDF pozostają dostępne”.

Deliver the live link when actually running, plus the direct stable HTML/PDF and editable project location. A stopped/unavailable live preview is not a failed deck export; explain its state accurately. Installation itself does not start a server.


## Default viewing destination — D99 / v4.27

After a permitted local live session starts or is reused, call `node scripts/open-preview.mjs --project PROJECT --lang en|pl` once to request its matching URL in the system default external browser. Reuse that tab after edits. The opener neither starts a server nor changes the default browser; live sessions remain bounded foreground tasks with Stop/idle expiry. If no matching live session is running, it opens the checked saved HTML through the OS file association. Remote/headless hosts cannot open a window on the user’s device; follow DELIVERY.md’s downloadable-file route. Do not claim ordinary chat links force external opening or that an OS request proves visible rendering.


## Local viewing after downloading from Claude/cloud — D100

A downloaded standalone HTML can be opened directly in a browser with its fonts/images/PDF; no Node, Chrome installation or server is needed for that viewing step. Present mode and keyboard navigation work there. It is an offline snapshot.

Continuing to edit in the same agent conversation does not require a ZIP download or extraction. Only if the user chooses to move/run the generated project locally from a cloud session, download the **optional complete current project ZIP**, unpack it and open that folder in a local agent with filesystem access. Ask: “Start live preview for this project and open it in my external browser.” The agent should use the existing Node20+ and the commands below; serving and opening a checked completed project do not require Playwright, Chrome or pdf-lib. Those tools are for later generation/export and image ingestion. Never propose installing the full PDF toolchain merely to view an existing checked deck. If Node is unavailable, keep direct HTML viewing and explain that specific requirement before any installation.

```sh
node scripts/live-preview.mjs --project /absolute/unpacked-project
```

Keep that bounded foreground command running. From another terminal in the same local environment (or the local agent’s task), request external opening:

```sh
node scripts/open-preview.mjs --project /absolute/unpacked-project --lang pl
```

Use --lang en for English. Open the actual URL returned by the local server; a cloud session’s 127.0.0.1/localhost points to that cloud machine, not the user’s computer. Do not add tunnels, public hosting, sync services or daemons for this handoff.

Live refresh follows checked files saved in that **same local folder**. It does not copy later cloud-Claude changes into a previously downloaded ZIP/HTML. A user continuing edits in cloud Claude downloads the current artifacts again; a user seeking automatic refresh needs edits saved locally by a permitted agent. Explain this distinction once when offering live preview. Stop and idle expiry remain unchanged.
